# Docker Compose – Developer Workflows

This guide covers common day-to-day tasks when working with the **Docker Compose** setup (`homenet-service` + `homenet-postgres-db`).

> **Prerequisite:** Make sure Docker Desktop is running and you have a valid `.env` file (copy from `.env.example` if needed).

---

## First-Time Setup

If this is your **first time** setting up the project with Docker:

1. Install [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) and make sure it's running.

2. Copy the example env file:
   ```powershell
   copy .env.example .env
   ```

3. Fill in the required values in `.env` (JWT secret, Cloudinary keys, etc.). The database credentials are already pre-filled.

4. Build and start the stack:
   ```powershell
   docker compose up --build
   ```
   This will pull PostgreSQL, build the NestJS app, and start everything.

5. Once the stack is up, apply migrations and seed the database:
   ```powershell
   docker compose exec homenet-service npx prisma migrate dev
   docker compose exec homenet-service npx prisma db seed
   ```

6. The API is now running at **http://localhost:3000** and Swagger docs at **http://localhost:3000/api/docs**.

---

## Starting & Stopping the Stack

```powershell
# First time / after Dockerfile changes
docker compose up --build

# Subsequent starts
docker compose up

# Run in background
docker compose up -d

# Stop everything
docker compose down

# Stop AND delete the database volume (fresh start)
docker compose down -v
```

## 1. Running a Prisma Migration (you created a new migration)

When **you** change `prisma/schema.prisma` and need to generate a new migration:

1. Make sure the stack is running:
   ```powershell
   docker compose up -d
   ```

2. Run the migration:
   ```powershell
   docker compose exec homenet-service npx prisma migrate dev --name <migration_name>
   ```
   This will:
   - Generate a new SQL migration file in `prisma/migrations/`
   - Apply it to the database
   - Re-generate the Prisma Client

3. **Commit** the new migration files in `prisma/migrations/` to Git.

---

## 2. Adding a New npm Package

When you need to add a new package (e.g. `axios`):

1. Make sure the stack is running:
   ```powershell
   docker compose up -d
   ```

2. Install the package inside the container:
   ```powershell
   docker compose exec homenet-service npm install axios
   ```
   For dev-only dependencies:
   ```powershell
   docker compose exec homenet-service npm install --save-dev @types/axios
   ```
   This updates both `package.json` and `package-lock.json` (which are bind-mounted back to your host).

   > **Never edit `package-lock.json` manually.** It's auto-generated by `npm install`.

3. Rebuild the container so `npm ci` bakes in the new lockfile:
   ```powershell
   docker compose down
   docker compose up --build
   ```

4. **Commit** both `package.json` and `package-lock.json` to Git.

> **Why rebuild?** The `node_modules` inside the container is separate from your host. Docker uses `npm ci` which reads `package-lock.json` to install exact versions. A simple `docker compose up` won't detect changes — you need `--build` to re-run the install step.

## 3. A Teammate Pushed New Migration Files

When you **pull** from Git and there are new files in `prisma/migrations/` that you haven't applied yet:

1. Pull the latest code:
   ```powershell
   git pull
   ```

2. Make sure the stack is running:
   ```powershell
   docker compose up -d
   ```

3. Apply the pending migrations inside the container:
   ```powershell
   docker compose exec homenet-service npx prisma migrate dev
   ```
   This will:
   - Detect the unapplied migration files
   - Run them against your local database
   - Re-generate the Prisma Client

4. If you want a **completely fresh database** instead (wipes all data):
   ```powershell
   docker compose down -v
   docker compose up --build -d
   docker compose exec homenet-service npx prisma migrate dev
   ```

---

## 4. Running Prisma Seeds

When you want to seed the database with existing data:

1. Make sure the stack is running:
   ```powershell
   docker compose up -d
   ```

2. Run the seed:
   ```powershell
   docker compose exec homenet-service npx prisma db seed
   ```
   This runs `prisma/seeds/seed.ts` which handles all seeds in the correct order (roles → areas → properties).

---

## 5. Wiping the Database (Fresh Start)

When you want to completely reset the database and start from scratch:

1. Stop the stack and delete the database volume:
   ```powershell
   docker compose down -v
   ```

2. Start the stack again:
   ```powershell
   docker compose up -d
   ```

3. Apply all migrations on the fresh database:
   ```powershell
   docker compose exec homenet-service npx prisma migrate dev
   ```

4. Re-seed the data:
   ```powershell
   docker compose exec homenet-service npx prisma db seed
   ```

## Quick Reference

| Task | Command |
|---|---|
| Start stack | `docker compose up -d` |
| Start stack (rebuild) | `docker compose up --build -d` |
| Stop stack | `docker compose down` |
| Stop + wipe DB | `docker compose down -v` |
| View logs (all) | `docker compose logs -f` |
| View API logs only | `docker compose logs -f homenet-service` |
| View DB logs only | `docker compose logs -f homenet-postgres-db` |
| Shell into API container | `docker compose exec homenet-service sh` |
| Run Prisma migration | `docker compose exec homenet-service npx prisma migrate dev --name <name>` |
| Apply pending migrations | `docker compose exec homenet-service npx prisma migrate dev` |
| Reset DB completely | `docker compose exec homenet-service npx prisma migrate reset --force` |
| Seed database | `docker compose exec homenet-service npx prisma db seed` |
| Open psql | `docker compose exec homenet-postgres-db psql -U postgres -d homenet` |
| Rebuild after new package | `docker compose down && docker compose up --build` |
| Install package | `docker compose exec homenet-service npm install <package-name>` |
